## 1. Ground filtering

The pipeline uses a progressive morphological filter over the per-cell minimum elevation surface:

> “open the minimum surface with windows of growing size and mark as object any cell that the opening pushes down further than a slope-dependent tolerance allows.”  
> — [ground.py:3](src/microrelief/ground.py:3)

For each window, it performs a grey opening and applies:

\[
T=\min(s \cdot w + dh_0,\ dh_{\max})
\]

as implemented here:

> `opened = grey_opening(...)`  
> `tolerance = min(params.slope_threshold * window_m + params.elevation_threshold_m, params.max_elevation_m)`  
> — [ground.py:87](src/microrelief/ground.py:87)

The recorded production parameters are:

- cell: `0.5 m`
- `max_window_m = 4.0`
- `slope_threshold = 0.3`
- `elevation_threshold_m = 0.3`
- `max_elevation_m = 3.5`
- downstream basis thresholds: `k_min_returns = 1`, interpolation radius `2.0 m`

— [provenance.json:86](viewer/provenance.json:86)

Despite its name, `max_window_m=4.0` produces actual widths of 1.5, 2.5, and 4.5 m because the radius doubles:

> “`max_window_m=4` and `max_window_m=6` yield exactly the same schedule.”  
> — [ground.py:55](src/microrelief/ground.py:55)

Why those values:

- `cell`, `max_window_m`, `slope_threshold`, `elevation_threshold_m`, `k_min_returns`, and interpolation distance are explicitly recorded as uncalibrated—not empirically justified values.  
  — [provenance.json:96](viewer/provenance.json:96)

- `max_elevation_m=3.5` is the exception. The code says it was chosen from a measured tallest verified terrace riser of 2.98 m, allowing for the 0.2–0.3 m LiDAR error band.  
  — [cli.py:318](src/microrelief/cli.py:318)

- The recorded measurement output reports 16,596 candidates, a tallest verified riser of 2.98 m, and the operator’s decision to raise the cap to 3.5 m. It also says the cap is not reached by the production windows: their largest tolerance is 1.65 m.  
  — [live-smoke.md:294](docs/live-smoke.md:294)

Agreement with official ASPRS class 2, per class, with the majority-class null alongside:

| Measure | Result |
|---|---:|
| Ground recall | 0.9992618534 |

The underlying counts are TP 7,809,752; FN 5,769; TN 3,817,874; FP 3,889,074.

## 2. Common grid

The production grid is recorded as one 3960 × 3960 grid, 0.5 m cells, EPSG:3763, origin `(-20990, 256990)`.  
— [provenance.json:19](viewer/provenance.json:19)

Its definition snaps the AOI bounds to cell multiples and calculates one row/column extent:

> `origin_x = math.floor(minx / cell) * cell`  
> `origin_y = math.ceil(maxy / cell) * cell`  
> — [grid.py:79](src/microrelief/grid.py:79)

There is no per-tile raster-window arithmetic in the implementation. One `Accumulator` allocates arrays of `grid.n_cells`; each tile’s points are converted directly to flat indices in those arrays:

> `n = grid.n_cells`  
> `self._min_all = np.full(n, ...)`  
> — [accumulate.py:81](src/microrelief/accumulate.py:81)

> `flat = row[inside] * self.grid.n_cols + col[inside]`  
> `self._min_all[cells] = np.minimum(...)`  
> — [accumulate.py:96](src/microrelief/accumulate.py:96)

After each `add`, only common-grid aggregates remain:

> “only per-cell aggregates (indexed by grid cell, not by point) survive. That is what makes tile order irrelevant and a mosaic step unnecessary: there is no per-tile window left anywhere to disagree with another one.”  
> — [accumulate.py:72](src/microrelief/accumulate.py:72)

Thus the code structurally prevents elementwise operations between per-tile windows: such windows are never constructed.

## 3. Voids

The recorded DTM basis fractions are:

- measured: `0.7460224722` — 74.6022%
- interpolated: `0.2520743419` — 25.2074%
- undetermined: `0.0019031859` — 0.1903%

— [provenance.json:27](viewer/provenance.json:27)

The closed-form model treats cell arrivals as Poisson:

\[
P(N=0)=e^{-\lambda},\qquad
\lambda=\rho c^2 f
\]

— [precheck.py:34](src/microrelief/precheck.py:34)

For the post-run honesty report, `f=1`, measured density `ρ=26.9902122232 pts/m²`, and cell size `c=0.5 m`:

\[
e^{-26.9902122232(0.5)^2}
=0.0011737482
\]

or 0.117375% expected empty cells. The exact recorded result is at [provenance.json:28](viewer/provenance.json:28).

This expectation concerns zero returns under the `f=1` reference model. It is not the expected measured-basis fraction: measured basis additionally requires the ground filter to accept the cell. That distinction is explicit in [density.py:91](src/microrelief/density.py:91).

## 4. Provenance and reproducibility

Do two runs produce identical bytes? Only under demonstrated constraints.

- Two real-data passes produced identical bytes for all six GeoTIFF bands; their records matched only after removing `created_utc`.  
  — [live-smoke.md:344](docs/live-smoke.md:344)

- The complete provenance JSON cannot normally be byte-identical because each run creates a fresh timestamp:  
  `created_utc=datetime.now(UTC).isoformat()`  
  — [provenance.py:130](src/microrelief/provenance.py:130)

- General real-data stability is not established, and cross-machine replay is unverified. The shipped record reports a corrupted read and a failed read whose cause remains open.  
  — [provenance.json:76](viewer/provenance.json:76)

- Synthetic same-machine exports are explicitly tested byte-for-byte.  
  — [test_export.py:152](tests/test_export.py:152)

Can a stranger reproduce from the record alone? No. The code itself says the record omits the acquisition route and exact code revision:

> “it is a verification anchor, not a self-contained recipe”  
> — [provenance.py:3](src/microrelief/provenance.py:3)

The hash covers package version, grid, parameters, item IDs, and input hashes, but not an exact source revision or dependency/runtime identity.  
— [provenance.py:114](src/microrelief/provenance.py:114)

Does CC-BY attribution reach the consumer? Yes for every exported GeoTIFF, the provenance sidecar, and the bundled viewer:

1. LAZ without a CRS:

   > `declares no CRS; refusing to assume one`

   > — [read.py:116](src/microrelief/read.py:116)

   > `a mosaic of two epochs is a product made of two moments — pass allow_mixed_epochs to accept and declare it`
