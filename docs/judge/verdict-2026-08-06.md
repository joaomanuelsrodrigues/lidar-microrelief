## 1. Ground filtering

The pipeline uses a progressive morphological filter over the per-cell minimum elevation surface. Increasing morphological openings are compared with a slope-dependent elevation tolerance: [ground.py:1](<src/microrelief/ground.py:1>), [ground.py:87](<src/microrelief/ground.py:87>).

The recorded production parameters are:

- Cell: `0.5 m`
- `max_window_m = 4.0`
- `slope_threshold = 0.3`
- `elevation_threshold_m = 0.3`
- `max_elevation_m = 3.0`
- Downstream basis parameters: `k_min_returns = 1`, `d_max_interp_m = 2.0`

These appear in the actual run record at [provenance.json:84](<viewer/provenance.json:84>). At 0.5 m resolution, `max_window_m=4` actually produces 1.5, 2.5, and 4.5 m windows; the parameter bounds the radius search rather than being an attained window width: [ground.py:46](<src/microrelief/ground.py:46>), [test_ground.py:94](<tests/test_ground.py:94>).

Why those values? The repository does not establish a real-site calibration for them. The run explicitly records all seven as `uncalibrated_thresholds`: [provenance.json:94](<viewer/provenance.json:94>). Synthetic tests provide partial behavioral justification:

- A gentle ramp retains over 98% ground: [test_ground.py:26](<tests/test_ground.py:26>).
- With the 3 m cap, all five synthetic terrace levels survive: [test_ground.py:39](<tests/test_ground.py:39>).
- Lowering only the cap below one riser damages the terraces: [test_ground.py:56](<tests/test_ground.py:56>).
- High canopy returns are mostly rejected: [test_ground.py:101](<tests/test_ground.py:101>).

That supports behavior on fixtures, not why these are correct values for Sistelo.

Agreement with official per-cell ASPRS class-2 presence is calculated at [ground.py:129](<src/microrelief/ground.py:129>). The actual output reports:

| Official class | Recall | Majority-class null |
|---|---:|---:|
| Ground | 0.9992618534 | 0.5034972851 |
| Non-ground | 0.4953807915 | 0.5034972851 |

Accuracy is `0.7490835382`; counts are TP `7,809,752`, FN `5,769`, TN `3,817,874`, FP `3,889,074`: [provenance.json:2](<viewer/provenance.json:2>).

There is only one overall majority-class accuracy null, computed as `max(prevalence, 1-prevalence)`: [ground.py:150](<src/microrelief/ground.py:150>). The repository does not report separate class-specific nulls; placing the same overall null beside both recalls should not be interpreted as a recall baseline.

## 2. Common grid

The common grid is defined by `Grid` and `grid_for_bounds()` in [grid.py:22](<src/microrelief/grid.py:22>) and [grid.py:65](<src/microrelief/grid.py:65>). Bounds are snapped outward to the cell lattice at [grid.py:79](<src/microrelief/grid.py:79>).

The actual run grid is 3960 × 3960, 0.5 m, EPSG:3763, origin `(-20990, 256990)`: [provenance.json:19](<viewer/provenance.json:19>).

On the production path:

1. One grid is created before inputs are read: [cli.py:208](<src/microrelief/cli.py:208>).
2. One `Accumulator(grid)` is created: [cli.py:165](<src/microrelief/cli.py:165>).
3. Each tile’s points are mapped directly into that grid: [accumulate.py:91](<src/microrelief/accumulate.py:91>).
4. Only common-grid extrema and counts survive each `add()`: [accumulate.py:103](<src/microrelief/accumulate.py:103>).
5. Surface arithmetic operates on those finished common-grid arrays: [surfaces.py:48](<src/microrelief/surfaces.py:48>).

There is consequently no production representation of a per-tile raster window on which elementwise cross-tile arithmetic could operate. This is strong structural evidence from the complete run path, though “never” cannot be proven beyond the repository version reviewed.

## 3. Voids

The committed run reports:

- Measured: `0.7460224722` = **74.6022%**
- Interpolated: `0.2520743419` = **25.2074%**
- Undetermined: `0.0019031859` = **0.1903%**

Source: [provenance.json:27](<viewer/provenance.json:27>).

The implementation defines measured cells as filter-ground cells satisfying the minimum-return count. Other cells are interpolated only if a measured neighbor is within 2 m; otherwise they remain undetermined: [density.py:56](<src/microrelief/density.py:56>).

The closed form is

\[
P(N=0)=e^{-\lambda},\qquad
\lambda=\rho c^2 f
\]

as implemented at [precheck.py:34](<src/microrelief/precheck.py:34>).

For the honesty report, `f=1`, measured density \(\rho=26.9902122232\) points/m², and \(c=0.5\) m:

\[
e^{-26.9902122232(0.5)^2}
=e^{-6.7475530558}
=0.0011737482
\]

or **0.117375%**. The report’s use of `f=1` is explicit at [density.py:87](<src/microrelief/density.py:87>), and the resulting value is recorded at [provenance.json:28](<viewer/provenance.json:28>).

This null predicts empty cells if every return were ground; it is not an expectation for the final 2 m interpolation-based `undetermined` state.

## 4. Provenance and reproducibility

Two runs do not have an unqualified byte-identity guarantee.

- A same-process synthetic test exports twice and verifies identical SHA-256 values for every GeoTIFF: [test_export.py:152](<tests/test_export.py:152>).
- Synthetic golden files lock output bytes on the development machine, but the test explicitly says the bytes depend on GDAL/libdeflate and cross-machine replay is unverified: [test_export.py:198](<tests/test_export.py:198>).
- The real-run record likewise says byte-identical replay was verified on only one machine: [provenance.json:76](<viewer/provenance.json:76>).

Therefore: identical bytes are demonstrated in constrained same-machine cases, not established generally or cross-machine.

A stranger cannot reproduce the run from `provenance.json` alone. It contains grid, parameters, input basenames and hashes: [provenance.py:33](<src/microrelief/provenance.py:33>), [provenance.py:101](<src/microrelief/provenance.py:101>). It does not contain:

- Source download URLs or acquisition instructions
- AOI geometry
- A Git commit or source-tree digest
- Python/GDAL/libdeflate environment identities

The reproducibility hash covers package version, grid, parameters, item IDs, and input hashes: [provenance.py:109](<src/microrelief/provenance.py:109>). It does not hash the implementation itself.

CC-BY attribution does reach a consumer of any exported GeoTIFF: the attribution string is defined at [provenance.py:22](<src/microrelief/provenance.py:22>) and attached to every raster inside the export loop at [export.py:39](<src/microrelief/export.py:39>) and [export.py:47](<src/microrelief/export.py:47>). Tests open each resulting file independently and verify the tag: [test_export.py:143](<tests/test_export.py:143>). Attribution also appears in the sidecar at [provenance.json:14](<viewer/provenance.json:14>).

The repository does not establish that attribution is embedded in standalone viewer PNGs.

   Refusal:

   Code: [read.py:101](<src/microrelief/read.py:101>).  
   Exercised by: [test_read.py:23](<tests/test_read.py:23>).

2. **No official ground class**

   Refusal:

   > `no points carry ASPRS class 2; without an official ground class there is nothing to compare our own filter against`

   Code: [read.py:116](<src/microrelief/read.py:116>).  
   Exercised by: [test_read.py:37](<tests/test_read.py:37>).

3. **A return outside the catalogue footprint**

   Refusal includes:

   > `return(s) fall outside its declared footprint … this is a corrupted read, not a property of the terrain — refusing rather than publishing a density divided by an exploded bounding box`

   Code: [read.py:128](<src/microrelief/read.py:128>).  
   Exercised by a regression based on an observed real-run failure: [test_read.py:188](<tests/test_read.py:188>).

Other explicit refusals include missing CRS, non-finite coordinates, unreadable LAS/LAZ, an all-empty minimum surface, no measured interpolation source, excessive grid size, mixed CRS, incomplete coverage, mixed epochs, and a sparse precheck exceeding its declared ceiling.

## README contradictions

1. **It misdescribes what is used for the official comparison.**

   README lines 6–8 say DGT’s “published rasters” appear in the comparison. The comparison actually uses `stats.n_ground_asprs > 0`, accumulated from ASPRS class 2 in the raw LAZ returns: [ground.py:141](<src/microrelief/ground.py:141>) and [accumulate.py:108](<src/microrelief/accumulate.py:108>). No DGT raster is read.

2. **It says every undetermined cell has “no usable return in the cell.”**

   README lines 12–15 make that claim, but measured status requires both `is_ground` and enough returns. A cell may contain returns and still be undetermined because the filter rejects it and no measured neighbor is within 2 m: [density.py:65](<src/microrelief/density.py:65>). The accurate statement is “no qualifying measured-ground value,” not necessarily “no usable return.”

3. **It says each interpolated cell records which measured cell it borrowed from, but that record is not exported.**

   README lines 93–94 imply this information travels with the product. `BasisResult` does hold `source_row` and `source_col` internally: [density.py:24](<src/microrelief/density.py:24>). But the published raster list contains only DTM, DSM, CHM, basis, `n_all`, and `n_ground_asprs`: [surfaces.py:25](<src/microrelief/surfaces.py:25>). Source indices are consumed while constructing the DTM and then omitted: [surfaces.py:52](<src/microrelief/surfaces.py:52>).

I could not rerun the tests in this read-only environment: plain `pytest` is unavailable, and `uv run pytest` cannot create its cache lock. The findings above therefore rely on committed code, tests, and recorded outputs rather than a fresh execution.
