## 1. Ground filtering

- Filter description: [ground.py:1](src/microrelief/ground.py:1)
- Opening and tolerance calculation: [ground.py:87](src/microrelief/ground.py:87)
- Final ground mask: [ground.py:98](src/microrelief/ground.py:98)

| `k_min_returns` | 1 | Explicitly uncalibrated; a measured cell must contain at least this many returns: [density.py:63](src/microrelief/density.py:63) |

## 2. Common grid

The common grid is defined by the frozen `Grid` class and `grid_for_bounds()` in [grid.py:24](src/microrelief/grid.py:24) and [grid.py:73](src/microrelief/grid.py:73). It snaps the origin outward to cell boundaries and derives one row/column shape at [grid.py:87](src/microrelief/grid.py:87).

The run constructs it once, before reading any tile:

> `grid = grid_for_bounds(...)`  
> `_read_inputs(paths, grid, ...)`

at [cli.py:300](src/microrelief/cli.py:300).

Each tile’s points are immediately mapped into that grid’s global row and column indices ([accumulate.py:91](src/microrelief/accumulate.py:91)). The accumulator then combines per-cell extrema and counts directly into its common one-dimensional arrays:

- Minimum/maximum/count combination: [accumulate.py:103](src/microrelief/accumulate.py:103)
- Official-ground combination: [accumulate.py:108](src/microrelief/accumulate.py:108)
- Only after all tiles are accumulated are those arrays reshaped into the common grid: [accumulate.py:114](src/microrelief/accumulate.py:114)

Consequently, no per-tile raster window is constructed at all. The elementwise operations occur only on completed common-grid arrays at [cli.py:304](src/microrelief/cli.py:304). This is stronger than merely checking matching transforms: per-tile windows do not exist in the data path.

## 3. Voids

The committed output reports:

- **Measured:** 0.7460224722 = **74.6022%**
- **Interpolated:** 0.2520743419 = **25.2074%**
- **Undetermined:** 0.0019031859 = **0.1903%**

Source: [provenance.json:27](viewer/provenance.json:27).

The code computes these as counts of the three basis codes divided by all common-grid cells: [density.py:95](src/microrelief/density.py:95).

The closed-form Poisson expectation is

\[
P(N=0)=e^{-\lambda},
\qquad
\lambda=\rho c^2 f
\]

as implemented at [precheck.py:51](src/microrelief/precheck.py:51).

For the honesty report, `f = 1`, measured density \(\rho=26.9902122232\) points/m², and cell width \(c=0.5\) m:

\[
e^{-26.9902122232(0.5)^2}
=e^{-6.7475530558}
=0.0011737482
\]

or **0.1173748%** expected empty cells. The inputs and result appear together at [provenance.json:28](viewer/provenance.json:28). The code explicitly identifies this as a reference model rather than a measured ground fraction: [density.py:91](src/microrelief/density.py:91).

## 4. Provenance and reproducibility

**Do two runs produce identical bytes?** Not as a general real-data claim.

- Exporting the same synthetic surfaces with the same already-created provenance object produces byte-identical TIFFs; the test hashes each file at [test_export.py:177](tests/test_export.py:177).
- Independent full runs cannot have identical provenance bytes because `created_utc` is generated from the current time: [provenance.py:132](src/microrelief/provenance.py:132).
- The committed real-run record explicitly says byte-identical replay is **not established**, cross-machine replay is unverified, and prior reads included one corrupted and one failed read: [provenance.json:76](viewer/provenance.json:76).

Therefore: synthetic same-object export is demonstrated; two clean real passes reportedly matched for raster bytes and record fields except the timestamp, but reliable real-data or cross-machine byte identity is not established.

**Can a stranger reproduce from the record alone?** No. The provenance module expressly says the record lacks the acquisition route and exact code revision and is “a verification anchor, not a self-contained recipe”: [provenance.py:3](src/microrelief/provenance.py:3). It does record filenames, SHA-256 digests, grid, parameters and package version ([provenance.py:108](src/microrelief/provenance.py:108)), but code changes enter the hash only through a manually maintained version ([provenance.py:116](src/microrelief/provenance.py:116)).

**Does CC-BY attribution reach the consumer?** Yes for every exported GeoTIFF and for the provenance sidecar.

- Attribution becomes a TIFF tag at [export.py:45](src/microrelief/export.py:45) and is attached to each raster at [export.py:75](src/microrelief/export.py:75).
- A test opens every exported band independently and verifies `CC BY 4.0`: [test_export.py:143](tests/test_export.py:143).
- The committed sidecar contains the complete attribution at [provenance.json:14](viewer/provenance.json:14).

The repository does not demonstrate that attribution is embedded in separately rendered PNGs.
