## 1. Ground filtering

The pipeline uses a progressive morphological filter over the per-cell minimum surface. Each iteration performs a grey opening and rejects cells whose elevation above the opened surface exceeds a slope-dependent, capped tolerance:

> `opened = grey_opening(surface, size=(size, size), mode="nearest")`  
> `tolerance = min(params.slope_threshold * window_m + params.elevation_threshold_m, params.max_elevation_m)`  
> `is_object |= (surface - opened) > tolerance`  
> — [ground.py:87](src/microrelief/ground.py:87)

The recorded production parameters are:

- `max_window_m = 4.0`
- `slope_threshold = 0.3`
- `elevation_threshold_m = 0.3`
- `max_elevation_m = 3.0`

They appear in [provenance.json:84](viewer/provenance.json:84).

At 0.5 m cells, the radius doubles, giving actual window widths of 1.5, 2.5, and 4.5 m—not a 4 m window:

> `radii.append(radius)` / `radius *= 2`  
> `return tuple((2 * radius + 1) * cell ...)`  
> — [ground.py:46](src/microrelief/ground.py:46), [ground.py:55](src/microrelief/ground.py:55)

Why those values:

- The code identifies the filter as Zhang et al. (2003), supporting the choice of the two `0.3` starting values: [ground.py:1](src/microrelief/ground.py:1).
- The repository explicitly records all seven production thresholds, including all four filter parameters, as uncalibrated: [provenance.json:94](viewer/provenance.json:94). Thus the repository does not establish that `4.0`, `0.3`, or `0.3` were site-calibrated.
- The `3.0 m` cap has synthetic evidence: the calibration record says all five terrace levels survive at 3.0 m, whereas one level is lost at 1.0 m: [CALIBRATIONS.md:52](CALIBRATIONS.md:52). The code also states that this cap, rather than tread/window comparison, governs riser survival: [ground.py:73](src/microrelief/ground.py:73).

Agreement is computed against whether each measured cell contains at least one official ASPRS ground return:

> `ours = is_ground[measured]`  
> `official = (stats.n_ground_asprs > 0)[measured]`  
> — [ground.py:137](src/microrelief/ground.py:137)

Production results, with the majority-class null beside them:

| Ground recall | 0.9992618534 | 0.5034972851 |

## 2. Common grid

The grid is defined by the frozen `Grid` record in [grid.py:22](src/microrelief/grid.py:22). `grid_for_bounds()` snaps the AOI outward to the common lattice:

> `origin_x = math.floor(minx / cell) * cell`  
> `origin_y = math.ceil(maxy / cell) * cell`  
> — [grid.py:65](src/microrelief/grid.py:65)

The production grid is 3960 × 3960, 0.5 m, EPSG:3763, origin `(-20990, 256990)`: [provenance.json:19](viewer/provenance.json:19).

The complete run path constructs one grid and one accumulator before reading tiles:

> `grid = grid_for_bounds(...)`  
> `acc, inputs, flight_dates = _read_inputs(paths, grid, ...)`  
> — [cli.py:208](src/microrelief/cli.py:208)

`_read_inputs()` creates that accumulator once and feeds each tile into it sequentially:

> `acc = Accumulator(grid)`  
> `for path in paths:`  
> `...`  
> `acc.add(batch)`  
> — [cli.py:165](src/microrelief/cli.py:165)

The accumulator stores only whole-grid one-dimensional aggregate arrays sized by `grid.n_cells`: [accumulate.py:81](src/microrelief/accumulate.py:81). Each tile is immediately mapped to common-grid indices and folded into those arrays: [accumulate.py:91](src/microrelief/accumulate.py:91).

Therefore, within the repository’s pipeline, per-tile raster windows are never constructed. There is consequently no representation on which cross-tile elementwise raster arithmetic could occur. This is structural evidence for the reviewed code; it cannot prove claims about code outside this repository/version.

## 3. Voids

The exact production fractions are:

- Measured: `0.7460224722` = **74.6022%**
- Interpolated: `0.2520743419` = **25.2074%**
- Undetermined: `0.0019031859` = **0.1903%**

Source: [provenance.json:27](viewer/provenance.json:27).

A measured cell must both pass the filter and contain at least `k_min_returns`; other cells are interpolated only if a measured cell is within 2 m:

> `measured = is_ground & (stats.n_all >= k_min_returns)`  
> `within = ... <= d_max_interp_m`  
> — [density.py:56](src/microrelief/density.py:56)

The closed form is the Poisson zero-count probability:

\[
P(N=0)=e^{-\lambda},\qquad
\lambda=\rho c^2f
\]

implemented as:

> `lam = density_pts_m2 * cell * cell * ground_fraction`  
> `return math.exp(-lam)`  
> — [precheck.py:34](src/microrelief/precheck.py:34)

The honesty report fixes `f = 1.0`: [density.py:87](src/microrelief/density.py:87). With recorded density `ρ = 26.9902122232 pts/m²` and `c = 0.5 m`:

\[
e^{-26.9902122232(0.5)^2}
=e^{-6.7475530558}
=0.0011737482
\]

or **0.117375%**, matching [provenance.json:28](viewer/provenance.json:28). This is an open-ground/null expectation, not an expectation using the measured ground-return fraction.

## 4. Provenance and reproducibility

**Do two runs produce identical bytes?** Not as a general claim.

- A synthetic same-machine test confirms identical GeoTIFF bytes when the exact same in-memory provenance object is reused: [test_export.py:152](tests/test_export.py:152).
- Synthetic golden bytes are explicitly machine-local because they depend on GDAL/libdeflate: [test_export.py:198](tests/test_export.py:198).
- On real data, four reads produced two clean byte-identical results, one corrupted-coordinate result, and one I/O failure: [live-smoke.md:204](docs/live-smoke.md:204).
- Independently, complete output directories from separately constructed runs cannot have identical bytes because `created_utc` is regenerated for each provenance record: [provenance.py:127](src/microrelief/provenance.py:127). The test deliberately confirms different timestamps despite equal reproducibility hashes: [test_provenance.py:34](tests/test_provenance.py:34).

**Can a stranger reproduce from the record alone?** No. The record supplies input basenames and SHA-256 values, grid, parameters, and package version, but not acquisition URLs or an exact source commit/tree digest. The hash covers only package version, grid, parameters, item IDs, and input digests: [provenance.py:112](src/microrelief/provenance.py:112). The module itself describes the record as a “verification anchor, not a self-contained recipe”: [provenance.py:1](src/microrelief/provenance.py:1).

There is also recorded evidence that a code change once produced different bytes under the same hash until the package version was manually bumped: [live-smoke.md:195](docs/live-smoke.md:195).

**Does CC-BY attribution reach the consumer?** Yes, for the published GeoTIFFs and provenance sidecar. Export attaches `provenance.attribution` to every raster’s tags: [export.py:39](src/microrelief/export.py:39), [export.py:47](src/microrelief/export.py:47). A test opens every exported band independently and checks for `CC BY 4.0`: [test_export.py:143](tests/test_export.py:143). The tracked provenance also contains the attribution text: [provenance.json:14](viewer/provenance.json:14).

## 5. Three demonstrated refusals

1. **LAZ with the wrong CRS**

   > `wrong_crs.laz declares EPSG:4326, AOI is EPSG:3763`

   Implemented at [read.py:101](src/microrelief/read.py:101) and demonstrated by [test_read.py:23](tests/test_read.py:23). The reason is explicit: the tile and AOI coordinate systems differ; the reader does not silently reproject.

2. **LAZ containing no official ASPRS ground class**

   > `no points carry ASPRS class 2; without an official ground class there is nothing to compare our own filter against`

   Implemented at [read.py:116](src/microrelief/read.py:116) and demonstrated by [test_read.py:37](tests/test_read.py:37).

3. **Retained return outside the catalogue-declared footprint**

   > `A return cannot be outside the box the catalogue derived from the returns, so this is a corrupted read, not a property of the terrain — refusing rather than publishing a density divided by an exploded bounding box`

   Implemented at [read.py:128](src/microrelief/read.py:128) and demonstrated by [test_read.py:188](tests/test_read.py:188).

Other explicit refusals include missing CRS, non-finite coordinates, sparse selections, mixed epochs, insufficient AOI coverage, oversized grids, and truncated catalogue responses.
