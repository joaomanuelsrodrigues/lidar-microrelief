## 1. Ground filtering

The pipeline uses its own progressive morphological filter over the per-cell minimum elevation surface:

> “A progressive morphological filter … open the minimum surface with windows of growing size…”  
> [src/microrelief/ground.py:1](src/microrelief/ground.py:1)

It fills holes temporarily, applies successive grey openings, and rejects cells whose elevation above the opening exceeds the tolerance:

> `opened = grey_opening(surface, size=(size, size), mode="nearest")`  
> `tolerance = min(params.slope_threshold * window_m + params.elevation_threshold_m, params.max_elevation_m)`  
> `is_object |= (surface - opened) > tolerance`  
> [src/microrelief/ground.py:87](src/microrelief/ground.py:87)

The committed run used:

- `cell = 0.5 m`
- `max_window_m = 4.0`
- `slope_threshold = 0.3`
- `elevation_threshold_m = 0.3 m`
- `max_elevation_m = 3.5 m`
- `k_min_returns = 1`
- `d_max_interp_m = 2.0 m`

These values are recorded at [viewer/provenance.json:88](viewer/provenance.json:88).

Actual morphological window widths are 1.5, 2.5, and 4.5 m. The radius doubles, and `max_window_m` bounds the radius search rather than naming an actual window:

> “At 0.5 m cells … `max_window_m=4` and `max_window_m=6` yield exactly the same schedule.”  
> [src/microrelief/ground.py:55](src/microrelief/ground.py:55)

Why these values:

- `0.5 m` matches the finest DGT published product: [CALIBRATIONS.md:8](CALIBRATIONS.md:8).
- `k_min_returns=1` is described as the weakest defensible definition of a measurement: [CALIBRATIONS.md:9](CALIBRATIONS.md:9).
- `d_max_interp_m=2.0` means four 0.5 m cells; the repository explicitly says this remains unvalidated pending a semivariogram: [CALIBRATIONS.md:10](CALIBRATIONS.md:10).
- `max_window_m=4.0`, `slope_threshold=0.3`, and `elevation_threshold_m=0.3` are explicitly uncalibrated defaults, not fitted site values: [CALIBRATIONS.md:14](CALIBRATIONS.md:14), [CALIBRATIONS.md:15](CALIBRATIONS.md:15), [CALIBRATIONS.md:16](CALIBRATIONS.md:16).
- `max_elevation_m=3.5` is site-calibrated: the tallest verified terrace riser was 2.98 m, and the old 3.0 m cap left only 2 cm—inside the stated 0.2–0.3 m LiDAR error band. The CLI comment records that reason directly: [src/microrelief/cli.py:412](src/microrelief/cli.py:412). At the default windows this cap is not reached because the largest computed tolerance is only 1.65 m: [CALIBRATIONS.md:17](CALIBRATIONS.md:17).

Official class 2 is used only as the comparison reference:

> `official = (stats.n_ground_asprs > 0)[measured]`  
> [src/microrelief/ground.py:141](src/microrelief/ground.py:141)

The committed results, with the majority-class null beside them, are:

| Ground recall | 0.9992618534 | 0.5034972851 |

## 2. Common grid

The grid is defined by `Grid` and `grid_for_bounds` in [src/microrelief/grid.py:24](src/microrelief/grid.py:24) and [src/microrelief/grid.py:73](src/microrelief/grid.py:73). It snaps the AOI outward to a single lattice:

> `origin_x = math.floor(minx / cell) * cell`  
> `origin_y = math.ceil(maxy / cell) * cell`  
> [src/microrelief/grid.py:87](src/microrelief/grid.py:87)

The run creates that grid once, passes it to one accumulator, and only then derives every downstream array:

> `grid = grid_for_bounds(...)`  
> `acc, ... = _read_inputs(paths, grid, ...)`  
> `stats = acc.finish()`  
> [src/microrelief/cli.py:300](src/microrelief/cli.py:300)

There are no per-tile rasters to combine. Every tile is immediately folded into grid-indexed arrays:

> “only per-cell aggregates (indexed by grid cell, not by point) survive.”  
> [src/microrelief/accumulate.py:72](src/microrelief/accumulate.py:72)

The actual updates are against the same flattened grid indices:

> `self._min_all[cells] = np.minimum(...)`  
> `self._max_all[cells] = np.maximum(...)`  
> `self._n_all[cells] += counts`  
> [src/microrelief/accumulate.py:103](src/microrelief/accumulate.py:103)

Thus the code structurally rules out elementwise arithmetic between per-tile windows: no per-tile window arrays are created or retained. The committed common grid is 3960 × 3960 at 0.5 m, EPSG:3763: [viewer/provenance.json:19](viewer/provenance.json:19).

## 3. Voids

The committed DTM basis fractions are:

- Measured: `0.7460224722` — 74.602%
- Interpolated: `0.2520743419` — 25.207%
- Undetermined: `0.0019031859` — 0.190%

Source: [viewer/provenance.json:27](viewer/provenance.json:27).

The code calculates these over all grid cells at [src/microrelief/density.py:90](src/microrelief/density.py:90). A measured cell must both pass the ground filter and contain at least the required returns; interpolation is nearest-measured and limited by distance: [src/microrelief/density.py:65](src/microrelief/density.py:65), [src/microrelief/density.py:74](src/microrelief/density.py:74).

The closed form is

\[
P(\text{empty})=e^{-\lambda},
\qquad
\lambda=\rho c^2f.
\]

That implementation is explicit at [src/microrelief/precheck.py:51](src/microrelief/precheck.py:51).

For the honesty null, `f=1`, measured density `ρ=26.9902122 pts/m²`, and `c=0.5 m`:

\[
e^{-26.9902122(0.5)^2}
=e^{-6.7475531}
=0.0011737482
\approx 0.1174\%.
\]

The stored density and result are at [viewer/provenance.json:28](viewer/provenance.json:28). This is an open-ground Poisson reference, not an expectation fitted with the observed ground-return fraction; the code deliberately calls `expected_void_fraction(density, cell, 1.0)` at [src/microrelief/density.py:92](src/microrelief/density.py:92).

## 4. Provenance and reproducibility

**Do two runs produce identical bytes?** Not as a blanket guarantee.

- Two clean real-data passes produced byte-identical bytes for all six GeoTIFFs, with the provenance record identical except `created_utc`: [docs/live-smoke.md:344](docs/live-smoke.md:344).
- The complete output directory cannot be byte-identical because `created_utc` is generated anew on every run: [src/microrelief/provenance.py:132](src/microrelief/provenance.py:132).
- More importantly, four earlier reads included one corrupted coordinate and one outright read failure: [docs/live-smoke.md:204](docs/live-smoke.md:204). Later, 192 controlled reads had zero events, but the root cause remained open: [docs/live-smoke.md:282](docs/live-smoke.md:282).
- Cross-machine replay is explicitly unverified in the committed record: [viewer/provenance.json:79](viewer/provenance.json:79).

**Can a stranger reproduce from the record alone?** No. They can verify a rerun if they independently obtain the same files and software, but the record is not a self-contained recipe. The module says exactly that:

> “not the acquisition route or the exact code revision, so it is a verification anchor, not a self-contained recipe”  
> [src/microrelief/provenance.py:3](src/microrelief/provenance.py:3)

It records basenames and SHA-256 digests, grid, parameters, and package version—e.g. [viewer/provenance.json:34](viewer/provenance.json:34)—but not download locations, exact revision, platform, or full execution environment. Code changes reach the hash only through the manually maintained package version: [src/microrelief/provenance.py:116](src/microrelief/provenance.py:116).

**Does CC-BY attribution reach the consumer?** Yes for exported artifacts. The run’s full DGT CC BY 4.0 attribution is stored in provenance: [viewer/provenance.json:14](viewer/provenance.json:14). Export copies it into every GeoTIFF’s metadata tags:

> `"attribution": provenance.attribution`  
> `dst.update_tags(**tags, band=name)`  
> [src/microrelief/export.py:45](src/microrelief/export.py:45), [src/microrelief/export.py:73](src/microrelief/export.py:73)

The round-trip test checks every raster independently: [tests/test_export.py:143](tests/test_export.py:143).

## 5. Three explicit refusals

1. **A geographic/non-metric CRS**

   Message:

   > “Every threshold in this package is a length in metres; on degrees they would be applied unchanged and the output would be plausible and wrong. Reproject…”  
   > [src/microrelief/crs.py:27](src/microrelief/crs.py:27)

2. **Any LAS/LAZ containing NaN or infinite coordinates**

   Message:

   > `“… point(s) have non-finite {name} (a header scale/offset that decodes to NaN or inf); refusing to build a surface on it”`  
   > [src/microrelief/read.py:111](src/microrelief/read.py:111)

3. **A return outside the catalogue-declared tile footprint**

   Message:

   > “A return cannot be outside the box the catalogue derived from the returns, so this is a corrupted read, not a property of the terrain — refusing rather than publishing a density divided by an exploded bounding box”  
   > [src/microrelief/read.py:139](src/microrelief/read.py:139)
