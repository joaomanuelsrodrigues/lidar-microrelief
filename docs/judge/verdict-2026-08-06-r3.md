## 1. Ground filtering

The pipeline uses its own progressive morphological filter over the per-cell minimum elevation surface. It repeatedly applies a grey-scale morphological opening and rejects cells whose elevation above the opened surface exceeds a slope-dependent tolerance:

- Filter identification: [ground.py:1](src/microrelief/ground.py:1)
- Opening and tolerance calculation: [ground.py:87](src/microrelief/ground.py:87)
- Official ASPRS classification is used only afterward for comparison: [ground.py:129](src/microrelief/ground.py:129)

The recorded parameters are:

- `cell = 0.5 m`
- `max_window_m = 4.0`
- `slope_threshold = 0.3`
- `elevation_threshold_m = 0.3 m`
- `max_elevation_m = 3.0 m`

These are recorded at [outputs/provenance.json:84](outputs/provenance.json:84). Because the radius doubles, this setting actually runs 1.5, 2.5, and 4.5 m windows; the implementation is at [ground.py:46](src/microrelief/ground.py:46), and the exact schedule is asserted at [test_ground.py:94](tests/test_ground.py:94).

Why those values:

- The repository provides no empirical justification for `0.5`, `4.0`, `0.3`, or `0.3` in the code/output record. Indeed, every threshold is explicitly recorded as uncalibrated at [outputs/provenance.json:94](outputs/provenance.json:94).
- There is synthetic evidence for `max_elevation_m = 3.0`: a 1.5 m-riser hillside retains all five levels at a 3 m cap, while lowering the cap below one riser causes damage. See [test_ground.py:33](tests/test_ground.py:33) and [test_ground.py:56](tests/test_ground.py:56). That is synthetic validation, not calibration against measured Sistelo risers.

Agreement with official classification, with the same majority-class null beside each class:

| Official class | Recall | Majority-class null |
|---|---:|---:|
| Ground | 0.9992618534 | 0.5034972851 |
| Non-ground | 0.4953807915 | 0.5034972851 |

The output reports these at [outputs/provenance.json:6](outputs/provenance.json:6). Overall accuracy is 0.7490835382. The comparison covers 15,522,469 cells, with TP 7,809,752, TN 3,817,874, FP 3,889,074, and FN 5,769 at [outputs/provenance.json:2](outputs/provenance.json:2).

The null is the accuracy obtained by always predicting the more prevalent official class, calculated as `max(prevalence, 1-prevalence)` at [ground.py:150](src/microrelief/ground.py:150).

## 2. Common grid

The common grid is created once from the AOI bounds:

- Definition and outward snapping: [grid.py:65](src/microrelief/grid.py:65)
- Actual recorded grid—3960 × 3960, 0.5 m, EPSG:3763, origin `(-20990, 256990)`: [outputs/provenance.json:19](outputs/provenance.json:19)
- CLI creates it once and passes it into accumulation: [cli.py:208](src/microrelief/cli.py:208)

There are no per-tile raster windows in the processing path. Each tile’s points are immediately mapped to indices in the shared grid at [accumulate.py:91](src/microrelief/accumulate.py:91). Tile results update common one-dimensional accumulator arrays at [accumulate.py:103](src/microrelief/accumulate.py:103), which are reshaped only after every tile is consumed at [accumulate.py:114](src/microrelief/accumulate.py:114).

All later elementwise operations therefore concern arrays with that one grid shape—for example DTM assignment and CHM subtraction at [surfaces.py:48](src/microrelief/surfaces.py:48). Export also derives every raster’s dimensions and transform from `surfaces.grid` at [export.py:34](src/microrelief/export.py:34).

Thus the code structurally shows that pipeline elementwise arithmetic cannot occur between per-tile windows: no per-tile window arrays are ever constructed.

## 3. Voids

The final DTM basis fractions are:

- Measured: `0.7460224722` — 74.6022%
- Interpolated: `0.2520743419` — 25.2074%
- Undetermined: `0.0019031859` — 0.1903%

These are recorded at [outputs/provenance.json:27](outputs/provenance.json:27). The classifications are assigned explicitly at [density.py:70](src/microrelief/density.py:70): a cell is measured when classified ground with at least one return, interpolated if a measured cell is within 2 m, and otherwise undetermined.

The closed-form null is

\[
P(N=0)=e^{-\lambda},\qquad
\lambda=\rho\,c^2f.
\]

The implementation is at [precheck.py:34](src/microrelief/precheck.py:34). For the final report, `f=1`, explicitly chosen as an open-ground reference model at [density.py:91](src/microrelief/density.py:91).

Using recorded density \(\rho=26.9902122232\) points/m² and cell size \(c=0.5\) m:

\[
e^{-26.9902122232(0.5)^2}
=e^{-6.7475530558}
=0.0011737482,
\]

or 0.117375% expected empty. The recorded value is at [outputs/provenance.json:28](outputs/provenance.json:28).

This null is not the expected undetermined fraction after interpolation, nor does it use the observed ground-return fraction; it is the empty-cell expectation if every measured return could reach ground.

## 4. Provenance and reproducibility

**Do two runs produce identical bytes?** Qualified yes, not universally.

The checked-in final `outputs/` and `outputs_replay/` have identical SHA-256 hashes for all six GeoTIFFs. Their provenance sidecars differ because `created_utc` changes. The synthetic test also requires two exports to have identical raster hashes at [test_export.py:152](tests/test_export.py:152).

However, real-data repeatability is not established generally: the checked-in execution record says that of four reads, two were byte-identical, one produced a corrupted coordinate, and one failed outright at [docs/live-smoke.md:204](docs/live-smoke.md:204). Cross-machine identity is also explicitly unverified in the provenance at [outputs/provenance.json:76](outputs/provenance.json:76).

**Can a stranger reproduce from the provenance record alone?** No.

The sidecar records filenames, item IDs, input hashes, grid, parameters, and package version; its input schema is at [provenance.py:33](src/microrelief/provenance.py:33). It does not record download URLs, an exact source commit, dependency versions, GDAL/libdeflate versions, or a retrievable code artifact. The URLs happen to exist separately in `selection.json`, for example [outputs/selection.json:20](outputs/selection.json:20), but that is not the provenance record alone.

Furthermore, the reproducibility hash covers only package version, grid, parameters, item IDs, and input digests at [provenance.py:109](src/microrelief/provenance.py:109). A code change without a version bump is therefore invisible.

**Does CC-BY attribution reach the consumer?** Yes for consumers receiving any exported GeoTIFF or the provenance sidecar.

The full attribution is stored in the sidecar at [outputs/provenance.json:14](outputs/provenance.json:14). Export attaches it to every GeoTIFF’s metadata tags at [export.py:39](src/microrelief/export.py:39), and the test opens every band independently and checks for CC BY 4.0 at [test_export.py:133](tests/test_export.py:133).

## 5. Refusals

Three concrete examples:

1. **LAZ with the wrong CRS**

   Message: `wrong_crs.laz declares EPSG:4326, AOI is EPSG:3763`

   The refusal is implemented at [read.py:101](src/microrelief/read.py:101) and exercised with that message at [test_read.py:23](tests/test_read.py:23). The reason is that the tile and AOI grids use different CRSs; the reader does not silently reproject.

2. **LAZ with no ASPRS ground class**

   Message: `... no points carry ASPRS class 2; without an official ground class there is nothing to compare our own filter against`

   Implemented at [read.py:116](src/microrelief/read.py:116) and exercised at [test_read.py:37](tests/test_read.py:37).

3. **Mixed acquisition epochs**

   Message: `AOI spans 2 sorties (...); a mosaic of two epochs is a product made of two moments — pass allow_mixed_epochs to accept and declare it`

   Implemented at [tiles.py:299](src/microrelief/tiles.py:299) and exercised at [test_selection.py:102](tests/test_selection.py:102).

Other explicit refusals include missing CRS, non-finite coordinates, returns outside the catalogue footprint, incomplete coverage, excessive area, sparse expected coverage, empty grids, and grids exceeding the memory ceiling.
